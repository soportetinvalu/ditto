# Memoria Local (nombre provisional)

Implementación nativa **Swift + AppKit + SQLite**, solo macOS arm64, guiada por el informe REA ya existente de Ditto 3.25.113.0. No es un MVP de texto: el código guarda representaciones multiformato por ítem, recupera el historial, maneja grupos, favoritos, protecciones, buffers, papelera y operaciones de respaldo. **Eso no acredita paridad completa ni una app compilada:** la interfaz Swift/AppKit todavía necesita compilación y pruebas en macOS.

## Comportamiento incorporado

### Captura y privacidad

La primera apertura mantiene la captura **desactivada**. Activarla en Ajustes exige consentimiento y empieza desde los cambios posteriores, no desde el contenido preexistente. Lee `NSPasteboard.changeCount` por sondeo configurable (350 ms predeterminado). No existe API de cola histórica: cambios más rápidos pueden perderse; una copia que sobreviva a sueño/despertar se observa, no se reconstruye lo intermedio.

- Texto Unicode, RTF, RTFD, HTML, PNG/TIFF/JPEG, URLs y URLs de archivos se conservan en BLOB independientes, incluyendo orden de ítems y tipo nativo.
- Formatos privados/desconocidos: opcionales, desactivados inicialmente. Límites: 32 MiB y 256 representaciones por copia. Una copia que los exceda se **omite entera**, no se guarda mutilada.
- Los formatos marcados `ConcealedType`, `TransientType`, `AutoGeneratedType` y `com.agilebits.onepassword` se omiten. No es detección universal de secretos.
- Pausa y listas permitir/excluir por bundle ID exacto. La exclusión prevalece. Un origen desconocido se omite. La aplicación al frente es una aproximación al origen, no una atribución demostrada del pasteboard.
- Sin nube, red, listeners, cuenta ni telemetría en el código. Sin cifrado propio. La carpeta de historial usa permisos 0700 y el archivo 0600; FileVault y control de sesión siguen siendo responsabilidad del entorno.

### Panel y teclado

Barra de menús → panel compacto de filas alternas numeradas, filtros de grupo/favorito/papelera y buscador inferior. UI en español, apariencia sistema/clara/oscura. Atajo inicial **⌃⌥ `** (código físico 50). Ajustes conserva los tres preajustes y añade **Personalizado…**:

1. Abre **Ajustes…** desde el icono de la barra de menús.
2. En **Atajo global**, elige **Personalizado…** y pulsa **Grabar atajo**.
3. Pulsa una tecla con al menos un modificador **⌃ Control, ⌥ Opción, ⇧ Mayúsculas o ⌘ Comando**. Se muestra la combinación; una tecla sin modificadores se rechaza. **Esc** cancela la grabación, igual que cambiar de foco o cerrar Ajustes.
4. Pulsa **Guardar** para registrar y conservar el cambio entre aperturas. **Restablecer** prepara el atajo inicial; también requiere Guardar.

No se solicitan permisos de monitorización del teclado: el grabador solo recibe eventos de su ventana mientras tiene el foco. Carbon registra el atajo global mediante el código físico y los modificadores. Las etiquetas usan una tabla física ANSI (pueden diferir de las leyendas de un teclado español/ISO/JIS); cambiar la distribución no cambia la posición registrada. Esc se reserva para cancelar la grabación. Fn/Caps Lock no cuentan como modificadores; las teclas de función pueden necesitar Fn según la configuración del Mac.

macOS y otras apps pueden reservar combinaciones o interceptarlas antes de que lleguen al grabador. Si Carbon rechaza una combinación, Ajustes informa del error y conserva **el atajo anterior y sus preferencias**, sin desregistrarlo primero. Al arrancar no hay un registro previo que conservar: si el atajo guardado está ocupado, se informa y el icono sigue disponible para elegir otro. Comprueba la combinación en tu Mac; no se garantiza detectar todas las interferencias del sistema.

- `Enter`/doble clic: formato original; `Shift-Enter`: solo texto.
- Flechas para selección; `Espacio`: vista previa; `Escape`: ocultar.
- `⌘F`: buscar; `⌘C`: copiar sin eventos; `⌘E`: editar como copia de texto nueva.
- `⌥1…⌥9`: elegir/pegar las nueve primeras filas. Selección múltiple concatena texto con separador configurable; **no simula pegados secuenciales**.
- Menú Acciones/contextual: propiedades/alias, favorito, protección, fijar arriba/abajo, grupos/subgrupos, tres buffers, transformaciones, importación/exportación, respaldo, fusión de respaldo, compactación y papelera.

La búsqueda literal usa SQL parametrizado con `instr`: `%`, `_` y comillas no actúan como comodines ni SQL. `lower()` de SQLite no hace folding Unicode/acento completo. Regex es un **subconjunto restringido** de ICU: hasta 128 caracteres, sin grupos, alternativas, llaves, escapes ni más de un repetidor; se aplica a título/alias y primeros 8192 caracteres. No es el dialecto completo de Ditto.

### Foco inicial y marca de uso

Al abrir se muestran todas las copias activas (se limpian búsqueda y filtros anteriores). Sin capturas posteriores al último uso, se selecciona y enfoca ese elemento; con capturas nuevas, la copia con `last_seen` más reciente. Sin uso previo se elige la más reciente disponible; con historial vacío se enfoca el buscador. Fijar arriba/abajo sigue respetándose: si el objetivo está fuera de vista, se desplaza hasta él, sin deshacer los fijados. Si el último usado se eliminó, se elige entre las copias activas restantes.

Escribir desde la lista lleva el evento original al buscador y empieza un filtro nuevo; admite Shift/Opción y caracteres Unicode. `Tab`, clic y `⌘F` también enfocan búsqueda. Se conservan los atajos: **Espacio sigue abriendo la vista previa**, `⌥1…9` pega, flechas navegan, Esc oculta y Enter pega. Espacio se escribe normalmente una vez enfocado el buscador.

Cada fila ya usada muestra una franja **`NSColor.systemBlue`, 4 pt, radio 2 pt, altura completa** en el borde izquierdo, incluso seleccionada. Un clic simple marca sin pegar ni reordenar; doble clic, Enter/Shift-Enter, `⌥1…9`, copiar (`⌘C` o menú), pegar original/plano/transformado y pegar buffer registran uso después de escribir correctamente al portapapeles. Seleccionar por foco/flechas, previsualizar o abrir un menú no marca. La fila se invalida en el momento, sin reiniciar.

`clips.used_at REAL NULL` persiste el uso independientemente de «reordenar al usar» (`last_used` mantiene su función anterior). El esquema pasa de v1 a v2 con transacción, comprobación de columna antes del `ALTER TABLE` y copia de los `last_used` conocidos; usos antiguos que nunca se guardaron no se pueden reconstruir. La re-captura deduplicada **conserva la marca** y cuenta como captura nueva para el foco. Un mismo pegado múltiple marca todos sus elementos; si comparten timestamp, el desempate es el orden estable de presentación. Los respaldos v1 siguen validándose sin modificar el original; se migra únicamente la copia de trabajo. La fusión/JSON siguen siendo intercambio de contenido, no restauración exacta de uso.

### Pegar con seguridad

El panel recuerda la app al frente **antes** de activarse. Primero repone los datos originales en el pasteboard. Por defecto solo copia y devuelve foco: `⌘V` manual.

Si se habilita envío automático en Ajustes, una selección solicita Accesibilidad cuando falta (no al arrancar). No queda ningún pegado en espera del permiso. Con permiso, verifica la app exacta y el contador del pasteboard después de recuperar foco, y envía una sola pareja de eventos `⌘V`. Si cambia foco/portapapeles, falta destino o no se puede activar, cancela el envío y mantiene la copia para pegar manualmente. **Enviar eventos no prueba que la otra app haya aceptado el pegado**; no hay reintentos automáticos ni bypass de Secure Input/TCC.

### Historial y gestión no destructiva

SQLite WAL, claves foráneas, esquema versionado y transacciones/savepoints. Hash SHA-256 incluye tipos, tamaños y orden de ítems; copias idénticas activas aumentan contador/fecha sin duplicar BLOB. Favorito, protección y fijado son campos distintos, y los tres excluyen la purga automática.

Retención predeterminada: 30 días, 5000 copias, 512 MiB de payload activo. Esos presupuestos no incluyen overhead SQLite, backups ni papelera. Si los registros protegidos superan el presupuesto, se conservan: no es un límite duro del espacio en disco. La retención **mueve a papelera**, nunca elimina definitivamente. Desde Papelera se restaura o se elimina solo la selección tras confirmación; colisiones de deduplicación/alias abortan la restauración sin sobrescribir.

Respaldos: API SQLite `backup` + comprobación de integridad/esquema/relaciones, nombre nuevo obligatorio, nunca sobrescritura. La fusión acepta archivos de hasta 128 MiB en esta versión. Restaurar **fusiona copias activas** de una copia temporal del respaldo con la base actual; no cambia el archivo suministrado, no reemplaza el historial y no reincorpora papelera/buffers como snapshot exacto. Compactar usa checkpoint/VACUUM explícitos.

Archivo JSON propio v1: exporta selección activa con formatos/base64 y grupos; importa con límites/validación/ciclos y transacción. No acepta `.dto`, DB Windows ni protocolos Friends. Exportación estándar: texto UTF-8 o PNG si está disponible. Las URLs de archivos siguen siendo referencias al archivo; no se copian los archivos referidos. Las exportaciones son sensibles, sin cifrado, y solo se crean por acción explícita.

### Vista previa y edición

Los formatos originales se preservan para volver a pegarlos. Las imágenes se decodifican con límites de dimensiones/píxeles. HTML se muestra **como código**, sin WebKit, scripts ni cargas remotas; el texto de búsqueda/pegado plano usa extracción limitada de etiquetas/entidades, no un renderer HTML completo. RTF se extrae a texto para la vista. QR local con CoreImage (hasta 2000 bytes; sujeto a capacidad real).

El editor crea una copia **solo texto**, sin alterar el original. Guardar un contenido idéntico puede deduplicarse con una copia existente. No hay editor enriquecido ni vista HTML/RTF visual completa.

## Estructura

- `Sources/ClipCore/`: esquema, inserción/deduplicación transaccional, retención, backup/validación y políticas de captura. Código C de producción enlazado al SQLite del sistema.
- `Sources/MemoriaLocal/Store.swift`: modelos, consultas parametrizadas, SHA-256, metadatos, grupos, intercambio y respaldo.
- `Services.swift`: sondeo multiformato, filtros, auto-captura excluida, consentimiento AX, retorno de foco, hotkey Carbon y previews.
- `HistoryController.swift`: panel/AppKit, selección/teclado, acciones y gestión.
- `SettingsController.swift`: privacidad, límites, atajo, apariencia e inicio de sesión opt-in con `SMAppService`.
- `Shortcut.swift`: configuración física compatible con preferencias anteriores, conversión/validación/descripción, reemplazo seguro del registro y grabador first-responder sin monitor global.
- `App.swift`: ciclo de vida/barra de menús y `--self-check` sin portapapeles.
- `Tests/CoreTests/`: pruebas del núcleo real con SQLite real.
- `Tests/MemoriaLocalTests/`: XCTest de Swift y portapapeles **nombrado**, nunca `.general`.

## Ejecución automática para el ejecutor autorizado

La persona usuaria **no necesita ejecutar comandos**. El agente/ejecutor macOS con acceso previamente autorizado recibe esta carpeta y corre una sola entrada con un directorio de salida nuevo:

```sh
python3 scripts/macos_executor.py --output RUTA_AUTORIZADA_NUEVA
```

Ese flujo usa únicamente herramientas ya instaladas, exige host macOS arm64, ejecuta `swift test`, compila release arm64, ejecuta `--self-check`, forma `.app`, firma ad hoc local, verifica firma, adjunta fuentes y manifiestos, y escribe `macos-executor.log`/`result.json`. No instala Xcode, no abre la app, no concede permisos, no publica, no usa cuenta GitHub ni compra certificados. Si falta SDK/compiler/host devuelve código 77; un fallo de compilación/prueba conserva su salida y detiene el empaquetado.

La firma ad hoc **no es** Developer ID ni notarización. El bundle ID `local.memorialocal.app` y nombre son provisionales; no compartir una compilación como release hasta la auditoría y la aceptación TCC/UI de `docs/ACEPTACION-MACOS.md`.

Prueba portable local ya preparada:

```sh
python3 scripts/test_portable.py
```

Es una prueba de C/SQLite, **no de Swift/AppKit**. Si Linux carece de `sqlite3.h`, utiliza declaraciones ABI auxiliares de test enlazadas a la biblioteca SQLite real instalada. No hay motor simulado ni instalación de headers. El build macOS siempre usa el SDK real.
